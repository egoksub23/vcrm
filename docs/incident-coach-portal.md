# Coach portal hand-off

For whoever builds the "Report incident" button in the coach portal. The same text, with the school's real address filled in, is generated by Halo under
**Incidents > Setup > Coach portal & API > Hand-off guide**; send that copy, not this one.

## What you build

When a coach taps **Report incident**, the portal's **server** asks Halo for a one-time link, then opens the link for the coach: in a new tab, an iframe or a
web view. The student list travels server to server, so student names never appear in a web address.

```
coach taps Report  ->  portal server: POST launch (key, coach, activity, roster)
                   ->  Halo returns { url, expires_at }
                   ->  portal opens url  ->  coach sends the report
                   ->  Halo tells the school's roles, and posts "submitted" to the frame
```

Halo's address is a deployment setting and is not fixed yet. Never build the link yourself: use the `url` Halo returns. Each school has its own key, so one
portal can serve many schools.

## 1. Create a report link

```
POST {halo}/api/public/incident-intake/launch
Authorization: Bearer ik_live_xxxxxxxx
Idempotency-Key: <your own id for this tap>
Content-Type: application/json
```

```json
{
  "form": "cca",
  "coach":    { "id": "C-204", "name": "Rahim Ismail", "email": "rahim@school.test", "phone": "+60120000001" },
  "activity": { "id": "A-1187", "name": "Football U15", "venue": "Field 2", "date": "2026-11-11" },
  "roster": [
    { "student_id": "S-3321", "name": "Adam bin Yusof", "class": "9 Amanah",
      "guardians": [ { "name": "Yusof Ali", "email": "yusof@mail.test", "phone": "+60121110000" } ] }
  ],
  "return_url": "https://coach.example.edu.my/activities/A-1187"
}
```

`201 Created`

```json
{ "url": "https://<halo>/report/<token>", "expires_at": "2026-11-11T12:00:00.000Z", "mode": "live" }
```

| Field | Rules |
| --- | --- |
| `form` | `"cca"` (the only form today). |
| `coach` | `id` and `name` required. `email` and `phone` optional. The coach is recorded as given and is **not** logged in to Halo. |
| `activity` | `id` and `name` required. `venue` and `date` (`YYYY-MM-DD`) optional. |
| `roster` | A list (it may be empty), at most 200 students. Each needs `student_id` and `name`; `class` and `guardians` (at most 4) are optional. |
| `guardians` | Optional. If sent, Halo can tell the parent or guardian role by email. If not, "tell the parent" stays a step for staff. Contact details never go to the coach's browser. |
| `return_url` | Optional. Must be on one of the addresses registered for the key. |
| `Idempotency-Key` | Optional but recommended. The same value returns the same link, so a retry is safe. |

Errors are `{ "error": { "code", "message", "field"? } }`:

| Status | `code` | Meaning |
| --- | --- | --- |
| 400 | `invalid_request` | Read `field` and `message`. The message never repeats the roster. |
| 401 | `invalid_key` | Missing, wrong or revoked key. |
| 403 | `missing_scope`, `not_enabled` | The key lacks the `launch` scope, or Incidents is switched off for the school. |
| 422 | `template_not_supported` | The school's template has no category the form files under. Ask the school to use the School Incident Management template. |
| 429 | `rate_limited` | Wait and retry. |
| 5xx | `server_error`, `not_configured` | Try again; `not_configured` means the server's public address is not set. |

## 2. Open the link

The link works for **2 hours**, files **one** report, needs **no cookies and no sign-in**. Sending the same report again returns the same reference.

```html
<iframe src="{url}" allow="camera" title="Report an incident" style="width:100%;border:0"></iframe>
```

Halo only allows framing from the addresses registered for your key (the school adds them under **Coach portal & API**). Any other site sees a blank page.
The report page sets no `X-Frame-Options`; framing is controlled by `Content-Security-Policy: frame-ancestors` from the link itself.

### Messages to your page

`window.postMessage`, always check `event.origin` is Halo's address. They carry no names or answers.

```json
{ "source": "halo-incident", "type": "ready" }
{ "source": "halo-incident", "type": "resize", "height": 640 }
{ "source": "halo-incident", "type": "submitted", "reference": "INC-2026-31" }
{ "source": "halo-incident", "type": "error", "code": "link_expired" }
```

* `resize`: set the frame's height to this so the page never needs a second scrollbar.
* `submitted`: close the frame or return the coach to the activity.
* `error`: `link_expired` or `invalid_link`. Call launch again and reopen.

### Web views

Turn on JavaScript and DOM storage. Allow the file chooser (Android: `onShowFileChooser`) and the camera (iOS: a camera usage description). If the camera is
not available the photo button falls back to the phone's file picker. If storage is blocked the draft is kept in memory instead (it is lost on a refresh).

## 3. Return to Play warnings (optional, never block anyone)

```
GET {halo}/api/public/clearances?student_ids=S-3321,S-3322
Authorization: Bearer ik_live_xxxxxxxx
```

```json
{ "clearances": [ { "student_id": "S-3321", "type": "concussion", "not_before": "2026-11-20", "incident": "INC-2026-31" } ] }
```

Show a warning beside the student. **Do not** stop the student being added to an activity. A date stops being a warning on the day itself.

## Testing

1. The school creates a **test key**. A test report is marked TEST everywhere and tells only the school's admins.
2. Run the simulated portal against it: `node scripts/incident-sim-portal.mjs --base https://<halo> --key ik_test_... --submit --origin https://<your-portal>`
3. Switch to the live key only when the school has signed off the end-to-end test (docs/incident-e2e-test.md).

## Rules

HTTPS only. Keep the key on your server (never in the page or the app). The school can rotate or revoke it at any time; revoking also ends every link it
issued. Rate limited per key. Photos: up to 5 per report, 10 MB each, JPEG/PNG/WebP/HEIC/PDF, added within 30 minutes of sending. Do not log or keep the
roster beyond what you already hold, and never put a student's name or id in a web address you build.
